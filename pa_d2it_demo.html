Put the model's capacity where the risk is

Perception-Aware Dynamic Diffusion Transformers for safety-critical scene generation

Jainish Patel & Meenakshi Rajpurohit

Each image is cut into a 16×32 grid of 512 cells. Only 128 of them get high-detail tokens; the rest are coarse. Every strategy below spends the same 128 cells, the same 896 tokens, the same 26.9 GFLOPs — the only thing that changes is where the detail goes.


What we measured

DiT-S, 6000 steps, 3 seeds, native-resolution 256×512 Cityscapes crops. Noise floor — two identical configurations retrained — is ; differences smaller than that are not resolvable.

Two things decide the outcome

 

Fragmentation. Every boundary between a coarse and a fine cell is a seam the model has to reconcile. Scattered allocations create hundreds of them; importance creates 62 because pedestrians are contiguous. Background error tracks this almost perfectly (ρ = 0.90).

 

Targeting. Coherence alone is not enough. The block has the fewest seams yet does worse, because a rectangle only catches 61% of pedestrian cells versus importance's 76%. You need both.

The result we did not expect

All five mixed strategies use 896 tokens / 26.9 GFLOPs. Uniform-coarse uses 512 tokens / 13.6 GFLOPs — half the compute — and beats every one of them. Uniform-fine at 2048 tokens is better still. Mixing two token sizes costs more than the extra detail buys, at this model scale.

A measurement artefact we caught

On downscaled full frames, entropy appeared to beat importance by 13× the noise floor, reproducibly across seeds. But a pedestrian was then a median 18.5 px tall — smaller than half a latent cell — so a fine token aimed at one had nothing to resolve, and texture-seeking won by default. On native-resolution crops (median 68 px) that advantage vanishes entirely: Δ drops to 1.0× floor and the sign flips between seeds. Same code, same compute, same architecture — only the pixels per pedestrian changed.
